LIMITS TO STATE
The limits that apply (copied from docs/api/CHUNK_A_CORRECTIONS.md item 1):
- Relation extraction from FIR text measured F1 0.32 on an independent held-out set.
- Identifiers (phone, Aadhaar, PAN, UPI, vehicle) were strong.
- IFSC codes are not extracted.
- There is no OCR (typed text only).
- CDR and bank CSV files must use the exact column names.
- All tuning data was synthetic.
- The 0.70 chip threshold was chosen after looking at one case and is labelled not evaluated.
- Break results ignore unobserved links.
- The audit hash chain is unkeyed (a person with file access can rewrite it, and removal of the last entries is not detectable).
- The login limiter counts failures per user name.
- File permissions on the secret key are not enforced on Windows.
- The live event-stream keepalive was not tested against a running server.
Additional Chunk C limits:
- The web unit tests cover pure functions and server-side rendering of views, not a real browser.
- The layout was not checked on any screen size other than 1366x768.
- npm reported vulnerabilities in development dependencies (not production runtime).

PAGES
- #/login: User authentication with credentials against /api/auth/login, rate-limiting retry seconds display, token handling via sessionStorage, and session clearing on logout.
- #/case/<id>/overview: Case facts header, verbatim disclaimer banner, priority leads ranked by money flow with role chips and evidence links, structural metric toggles (explanation only, not ranking), mule account leads table, burner phone leads table, and system limitations modal trigger.
- #/case/<id>/intake: Document upload (.txt and pasted text), CDR CSV upload, bank transactions CSV upload with required column references, SSE extraction and analysis job progress bars with polling fallback, row validation error table, and documents list with status, characters, and hashes.
- #/case/<id>/graph: Cytoscape link analysis canvas with node and relation type toggles, leads-only default filter, isolated nodes toggle, instant centering search, zoom-dependent label policy, and collapsible node/edge inspector panels with FIR excerpts and CSV row references.
- #/case/<id>/people: Searchable and sortable directory of individuals in the case, aliases, role chips, owned phones, controlled accounts, associated documents, and suggested same person cross-references.
- #/case/<id>/break: Courier break analysis between investigator-selected Group A and Group B (up to 200 members each, no overlap), cut size and member list, direct link indicator, unowned bridging phone numbers, verbatim server note and disclaimer, and Show on Graph navigation button. Restricted to analyst role.
- #/case/<id>/timeline: Aggregation by day and hour, hand-written SVG bar charts for calls and transfers volume with keyboard-focusable bars showing exact counts, and first-seen identifier timestamps table.
- #/case/<id>/evidence/doc/<doc_id>: Document text display with non-overlapping and overlap span segmentation, entity/relation property inspector, character counts, and raw/text SHA-256 hashes with copy buttons.
- #/case/<id>/evidence/rows/<file>?rows=...: Tabular viewer for raw CSV records from CDR or bank transactions with row numbers, file hash, and 200-row query limit notice.
- 404 Not Found: Fallback view for unmapped routes with a link returning to case overview.

HOW TO START THE SERVER
1. Load synthetic demo case:
   .\.venv311\Scripts\python.exe scripts/load_demo_case.py

2. Start backend API service on port 8000:
   .\.venv311\Scripts\python.exe scripts/run_api.py --port 8000

3. Start frontend development server on port 5173:
   npm --prefix web run dev

4. Open web user interface:
   http://localhost:5173
